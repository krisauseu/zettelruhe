# Finanz-Aggregate nur über Next.js schreiben

Kritische Schreibpfade — Festschreibung, Nummernkreise, Buchungsjournal, Kassenbuch, Rechnungs-/Beleg-Statusübergänge und vergleichbare Invarianten — laufen **ausschließlich** über Next.js Server Actions / Route Handlers / Domain-Services; der Browser schreibt nicht direkt per PocketBase-SDK in diese Collections. PocketBase-API-Rules sperren Client-Writes auf Finanz-Collections; Next schreibt mit Admin-/Service-Rechten nach geprüften Invarianten. Begründung: GoBD-Mindeststandard (ADR-0004) braucht atomare, serverseitig erzwungene Operationen (z. B. Nummer + Status + Journal), die reines Client-CRUD und verteilte Hook-Logik nicht zuverlässig liefern. Nicht-kritische Stammdaten dürfen technisch einfacher sein, der bevorzugte Weg bleibt Next.
